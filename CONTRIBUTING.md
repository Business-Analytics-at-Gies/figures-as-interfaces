# Contributing

Thank you for helping build this.

- Start from an issue. If none fits, open one first so the scope is agreed.
- Fork or branch, then open a pull request against `main`. Direct pushes to `main` are disabled.
- Every change to logic comes with a test. Run `pytest` before you open the PR.
- Keep dependencies pinned in `pyproject.toml`.
- No network calls in tests.
- If you used an AI assistant, say so in the PR description, the same way attribution works in the courses.
- Be kind in reviews. Reviews are about the code.

Read the paper first: https://arxiv.org/abs/2604.08491
